## 2. Requerimiento Funcional Crítico: REQ-01 (Gestión y Publicación de Cosechas)

### 2.1 Especificación Formal (IEEE 29148)
* **Identificador:** REQ-FUN-01
* **Título:** Publicación y Disponibilidad de Cosechas Agrícolas
* **Descripción:** El sistema permitirá a los agricultores registrados en el departamento del Valle del Cauca publicar sus cosechas especificando tipo de cultivo, cantidad en kilogramos, precio base por unidad y municipio de origen.
* **Prioridad:** Alta (Must Have)
* **Requisitos de Entrada:** 
  * Token de autenticación JWT válido emitido por el módulo de seguridad.
  * Cédula o registro de agricultor verificado por el administrador.
* **Requisitos de Salida:**
  * Registro exitoso en la base de datos relacional (PostgreSQL).
  * Generación de un identificador único (`product_id`) de tipo UUID o Long.

### 2.2 Evolución a Comportamiento (BDD / Gherkin)
Para garantizar la trazabilidad entre la especificación de requerimientos y las pruebas automatizadas del sistema, el requerimiento anterior se traduce en el siguiente escenario técnico:

```gherkin
Feature: Gestión de Publicaciones de Cosecha
  Como agricultor del Valle del Cauca
  Quiero publicar mis productos agrícolas en la plataforma
  Para que los compradores puedan visualizarlos y adquirirlos directamente

  Scenario: Publicación exitosa de una cosecha con datos válidos
    Given un agricultor autenticado con token JWT en el sistema
    When realiza una petición POST al endpoint "/api/v1/productos" enviando un JSON con tipo "Café", cantidad 500 y fecha de cosecha válida
    Then el sistema valida que la fecha no sea anterior a hoy y retorna un código HTTP 201 Created junto con el identificador único del producto
