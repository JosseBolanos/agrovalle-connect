# 📊 Retrospectiva del Sprint 1 — Grupo 8

Este documento presenta el análisis reflexivo del desempeño del Grupo 8 durante el ciclo del Sprint 1 para el proyecto AgroValle Connect, redactado formalmente en tercera persona bajo el enfoque metodológico de mejora continua.

---

### 🟢 1. ¿Qué funcionó bien? (Start / Madurez Técnica)
* **Adopción del Marco de Trabajo Ágil:** El equipo logró asimilar la dinámica del tablero Kanban en GitHub Projects de forma satisfactoria. La visualización de las subtareas técnicas facilitó el control del avance diario.
* **Alineación con Estándares Internacionales:** Se integraron con éxito los criterios de calidad de la norma ISO/IEC 25010 en la fase de modelado de datos, específicamente mediante la aplicación de restricciones JPA para asegurar la integridad de la base de datos PostgreSQL.
* **Control de Carga de Trabajo:** La implementación estricta del límite de trabajo en progreso (WIP Limit = 3) ayudó a mitigar la sobrecarga de actividades simultáneas en la columna de desarrollo.

---

### 🔴 2. ¿Qué no funcionó bien? (Stop / Bloqueos Identificados)
* **Gestión de Ramas y Sincronización:** Se presentaron retrasos operativos significativos al momento de realizar la integración de archivos locales mediante la consola. La falta de alineación en las líneas de tiempo provocó conflictos de mezcla (Merge Conflicts) complejos en documentos compartidos como el README.md.
* **Dependencia Tecnológica Local:** La configuración del entorno de desarrollo local experimentó bloqueos con los índices de Git, interrumpiendo momentáneamente el flujo continuo de commits del equipo.

---

### 🔵 3. Compromisos de Mejora Técnica (Continue / Plan de Acción)
* **Sincronización Preventiva Obligatoria:** El equipo se compromete de forma unánime a realizar descargas de actualización (git pull) antes de iniciar cualquier sesión de codificación para evitar la colisión de código fuente.
* **Uso Estratégico de la Interfaz Web:** Para la gestión de documentación y archivos de configuración que no requieran compilación directa en Java, se priorizará el uso de la interfaz gráfica web de GitHub para agilizar las entregas y mantener la estabilidad de la rama `develop`.
